# UI design traceability matrix

Source: *RFI Management System — Front-End User Interface Design*, v1.0, 15 Nov 2026 (18 pages).
Release: 6.0.0-ui (branch `feature/ui-design-v1`).

Status values:
- **Done**: implemented and covered by an automated test.
- **Done (manual)**: implemented and checked in the browser run; no dedicated automated assertion.
- **Partial**: implemented with a stated limitation.
- **Pending decision**: deliberately not decided; see [DECISION_REGISTER.md](DECISION_REGISTER.md).

The design says it is based on **SRS v2.0**, which we have not received. Everything below traces to the design document and to the confirmed SRS v1.0 rules. This release **does not claim SRS v2.0 compliance**.

## Deviations from the mockups (intentional)

| Mockup | Implementation | Reason |
|---|---|---|
| Final-remarks label "RE/ARE final remarks" (pages 8, 12, 14) | "RE/DRE" | DR-02: the client confirmed the deputy is "DRE" (Nov 2026). |
| Pending invitations shows "02" | "Not enabled" | There is no invitation workflow; inventing a count is not allowed (UD-12). |
| Inspector sequence shows role slots, each with "Select assigned user" | Ordered list of project members, each showing their single project role | A user has one role per project, so choosing the user fixes the DOC_03 field. Prevents assigning someone to a field they don't hold. |
| DOC_02 table shows Work status by default | Work status appears with the "Show Work_Status" toggle | Column S is hidden in the client workbook; the toggle follows the design's "Advanced / hidden workbook fields" section. |
| Sidebar menus identical for all roles (pages 3–12) | Role-specific menus from page 13 | Page 13 is the specification; the earlier pages are visual mockups. |
